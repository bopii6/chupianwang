## 六、转文字为什么走服务器（2026-11-28 加）

以前转文字在客户浏览器里跑，第一次用要先下 78MB 听写模型。实测公网出口只有 ~100KB/s，
78MB 要十几分钟，客户看到的就是「一直转圈」。现在改由服务器转：

```
客户浏览器 ── /api/copy/transcribe ──> 出片王（node） ──> sph-asr（faster-whisper, :8002）
                                          │
                                          └─ 视频已经在 .cache/sph-cache，直接抽音轨，不重下
```

实测（5 分 06 秒视频）：抽音轨 0.8s + 转写 31.8s，**总共 32–36 秒出 1718 字**，比浏览器快一个数量级。

- 页面先看 `/api/copy/meta` 的 `asrServer`：true 就走服务器，false 或失败自动退回浏览器本地转写
- 一次只跑一个（`ASR_MAX_SECONDS` 默认 3600 秒，超了直接报「视频太长」）
- whisper 中文常输出繁体，服务端用 opencc 统一转简体
- 看日志：`tail -f /var/log/sph-asr.log`；单条压测：`/usr/bin/python3.11 /opt/sph/asr-bench.py <视频路径>`

> 客户电脑上的**本地版**不受影响：模型就在本机，照旧走浏览器转写，不走服务器。
