单页讲义 · 零基础可学

Grok Bot 完整课件：从装好到自己会用

这不是提纲，也不是热帖汇编。你可以从头读到尾：先分清 Grok Bot 和 X 里的 Grok 有什么不同，再亲手交一件小事给它，学会怎么交代、何时再加助手，然后接上邮箱和日历，最后让它按点自动做。学完，你应当能独立用起来。

语言：简体中文 形式：一篇读完的讲义，不是翻页幻灯片 整理日期：2026年11月28日（北京时间）

开场

先把名字分清楚：Grok Bot 不是 X 里那个聊天窗口

很多人一听到「Grok」，会想到 X（原 Twitter）里能聊天的那个 Grok，或者点开一条帖子旁边出现的 Grok 图标。那些是另一套产品，用来问答、判断帖子靠不靠谱、做检索。今天这门课要学的，是 Grok Bot。

用人话说：Grok Bot 不是只跟你聊天的对话框。官方的说法是，它给你一组会干活的助手（Bot），这些助手共用一台云端电脑。你可以像交代同事那样给它任务，它能打开网站、使用你授权过的应用、把草稿写出来，必要的时候停下来等你点头，然后在你合上笔记本之后还能继续做。这篇讲法来自官方入门页 Get started 和指南 Grok Bot 101。

今天要学的：Grok Bot

在电脑或手机上单独打开的应用。助手有自己的云端桌面，能帮你查资料、整理邮件、起草回复、按日程重复做事。下载入口是 x.ai/bot。

不要和它搞混：X 里的 Grok

在 X 里聊天的 Grok，或帖子右上角那个 Grok 图标，用来读帖、提问、做检索。那些技巧不能直接当成 Grok Bot 的功能来用。

官方说法

官方把 Grok Bot 写成「带电脑的助手」。用起来像给同事发消息，但这位同事有一台一直开着的云端电脑：有桌面、有文件、有浏览器，也能打开你授权过的应用。你可以从手机和电脑进入同一批助手、同一段对话、同一台云端电脑。

这节课面向技术能力不强的同学。你不需要会写代码，也不需要先搭一套「AI 团队」。中文圈里读得最广的学习路径之一，是 @Mulight 在 2026年10月24日（北京时间）发的帖。他的收尾很适合当这门课的主张：

与其花几天研究别人怎么玩，不如先给自己创建一个 Bot，找件每天都要重复做的事情交给它。等它真的帮你省下时间，你自然就知道下一步该学什么了。

—— @Mulight，2026年10月24日（北京时间）

怎么读这份讲义

标了「官方说法」的，是文档或官方指南里写过的。标了「常见做法」的，是别人常用、但官网没有写成标准步骤的办法，不要把它当成官方保证。界面上的英文按钮，我会用中文解释，并保留官方英文，避免你对着软件找不到。

课程地图

本课先后学什么，学完能干什么

官方入门的顺序其实很清楚：先装好并登录，见到第一个助手，交给它一件真实任务，任务做对了再让它按日程重复。官方还把往后的成长写成三步：先当助手帮你找信息和起草，再把反复做的事交给专职助手，最后才考虑几个助手一起做更大的目标。见 Get started 和 Use cases。

@Mulight 建议的中文学习顺序，也和这条线一致：先跑通第一个 Bot，再结合官方 Guides 熟悉功能，想玩自动化和多助手协作时再往深走。不要先收藏几十篇教程。

第一课装好，开始用，先交一件小事下载、登录、见到第一个助手，当天就交出一件真实任务。先跑通 第二课怎么交代，它才真能干活把目标、来源、限制和交出品说清楚，并规定何时必须问你。会交代 第三课一个助手先做好一件事先专做一件事；什么时候再加助手，什么时候先别搭团队。再扩展 第四课接上日常工具邮箱、日历等官方连接方式；若提到微信，先听清隐私提醒。接工具 第五课让它按时自动做先把做对的方法留下来，再设例行任务，不要每次从头说。会自动 第六课用到工作与内容里用官方「工作场景」里适合小白的四个角色，先做好一个。能上路

学完这六课，你应当能做到四件事：自己装好并登录；把一件日常小事交代清楚并看完结果；在需要时接上邮箱或日历；把已经做对的事变成按时自动跑的例行任务。发送、下单、发布这类不能轻易撤回的动作，始终先经你同意。

第一课

装好、开始用，先交一件真实的小事

这课的目标只有一个：今天就让助手帮你做完一件真实的小事，并且结果你看过。不要一上来搭团队，也不要先收藏一堆教程。

这课学什么

你会完成官方入门的前四步：下载应用、登录、见到第一个助手、交给它一件真实任务。官方把这四步写在 Get started 里。

为什么重要

Grok Bot 的价值不在「它能聊」，而在「它能把一件事做完」。你如果只看演示、不交任务，就永远不知道它到底会不会按你的要求停下来等你确认。先跑通一次，后面怎么交代、怎么接工具、怎么设自动任务，才有着落。

怎么做

  1. 下载并打开应用。到官网 x.ai/bot 下载 Grok Bot，然后打开它。官方写明：桌面应用支持 macOS（苹果芯片和 Intel）、Windows（x64 和 Arm64）、Linux（x64 和 Arm64）。应用会自动检查更新；Linux 的 .deb / .rpm 安装包则通过系统的软件包管理器更新。
  2. 登录。在欢迎页选择 Sign in（登录），并在浏览器里完成。Grok Bot 使用你的 Cursor 账号，没有另一套单独的登录。如果你的使用权来自 SuperGrok 或 X Premium+ 等订阅，官方要求先做账号关联：电脑上到 cursor.com/bot/onboarding 选择 Link Grok Account（关联 Grok 账号）；手机上则在访问提示页完成关联，再选 Finished Linking? Refresh My Status（已关联？刷新我的状态）。公司若使用统一登录（SSO），按平时的公司登录方式即可。
  3. 见到第一个助手。一段简短介绍之后，应用会为你建好第一个助手，名字就叫 Grok Bot，并打开和它的对话。官方还提供一些已经按岗位搭好的起点，例如帮你看品牌被提到了没有的 Overheard、照看个人邮件和日历的 Tradbot、把会议记录做成回顾幻灯片的 Meeting Recap Deck。第一课不必急着换这些，先用默认的这一个就行。
  4. 交给它一件真实的小事。官方的建议是：像问同事那样说。讲清楚你要拿回什么、用哪些来源、有哪些限制、什么时候必须问你。需要你点头的动作，助手会弹出 approval card（批准卡片）并等待。第一件事请选你今天就用得上、又不必马上发出去的：查资料、对比选项、起草一封还不能发送的回复，都可以。

官方说法 · 哪些方案包含 Grok Bot

官方文档写：在 The X Subscription 上，Premium、Super、Ultra 包含 Grok Bot，可以是个人席位或团队席位。在旧的 Cursor 方案上，所有付费个人方案和自助开通的 Cursor Teams 也包含。你还可以关联个人的 SuperGrok、SuperGrok Plus、SuperGrok Heavy 或 X Premium+，或使用自助开通的 Grok Business 席位。具体以官网当时的 Get started 和方案说明为准，本课不引用可能过期的价格。

官方说法 · 隐私模式

Grok Bot 需要云端存储。若账号还停留在 Privacy Mode (Legacy)（旧版隐私模式），应用会请你先切换。若你在团队里，这项设置由团队管理员改。

第一件事可以这样交

下面两段可直接复制。它们改写自官方入门里的示例，并注明「先不要下单、不要发出去」。选一件和你今天真实相关的来做。

查行程，但不预订依据官方 Travel coordinator 示例改写
请帮我查一下：下周四去上海、周日返回的航班，不要红眼航班；再找两家位置靠市中心的酒店。只给我两个最好的组合，并写清票价、时长和不便之处。先不要预订任何东西。
做竞品速览依据官方 Competitive intelligence 示例改写
请查看下面这三家最近一周有没有新产品、改价或公开声明：（在这里换成你真正要跟的三个名字或网址）。给我一份短清单，每条带链接，并说明它对我对外怎么说这件事有什么影响。不要发布任何内容。

如果你更想先整理自己的事，也可以把材料贴进去，例如：「下面是我这周随手记的待办，请按紧急、今天要做、可以稍后三类整理，并标出你觉得还缺信息的条目。只整理，不要替我通知任何人。」这不是官方原句，但是同一条原则：先要结果，先不要对外行动。

手机上也能用同一套助手

官方写明：iPhone 需要 iOS 18 或更新，Android 需要 Android 9 或更新。到 App Store 或 Google Play 安装 Grok Bot，用同一个账号登录。手机和电脑看到的是同一批助手、对话、例行任务和云端电脑，不需要再买一次。手机上可以发消息、观看或接管那台云端电脑、批准动作，以及暂停或恢复例行任务。

你也可以对着它说，不必只打字。官方提供：电脑上用 Start voice input（开始语音输入，快捷键是 Cmd/Ctrl+D）；手机上用 Start dictation（开始听写）。若要实时对话，选择 Start voice chat（开始语音聊天）。

一个可照着做的小练习

今天就交一件事。选上面其中一个提示，把括号里的内容换成你的真实信息，发出去。等结果出来后，只做三件事：看它有没有按你的限制停下来、有没有列出依据或链接、有没有 invent（编造）你没提供的细节。觉得哪里不对，直接告诉它要改什么，再看一遍。

常见错误

  • 登录到一半就关掉浏览器，或把 SuperGrok / X Premium+ 的关联步骤跳过，然后误以为「我没权限」。
  • 第一句话就让它「帮我做一个完整的 AI 团队」或「从今天起全权管理我的生活」。官方建议先交一件具体任务。
  • 让它直接发邮件、发帖或下单。第一课请把「不要发送 / 不要预订」写进任务里，并亲自看批准卡片。
  • 把 X 里那个聊天 Grok 的用法，当成 Grok Bot 已经会做的事。
  • 结果不顺手就放弃。先指出哪里不对，让它改；官方接下来就会让你把做对的方法留下来，变成可重复的流程。

第二课

怎么交代，它才真能干活

助手不是猜心的。你说得越像交代一位靠谱同事，它越不容易跑偏。这课把官方那句「像问同事那样说」拆成你能反复使用的说法。

这课学什么

学会在一次交代里说清五件事：要达到什么目标、用哪些来源、有哪些限制、最后交出来的应是什么样子、哪些动作必须先问你。官方原文是：说出你要拿回什么、用哪些来源、有哪些限制，以及何时必须来问你。需要你同意的动作，助手会弹出批准卡片并等待。见 Get started。

为什么重要

含糊的句子最常见，比如「帮我看看邮箱」「帮我做一下下周」。它也许会做点什么，但你很难判断做没做对，也很难阻止它做过头。把交待说完整，不是为了把提示词写得很长，而是为了让结果可检查：你能对照「我要的是这三页短名单，并且一封都还没发出去」。

怎么做

你可以在心里过一遍下面五问。它们不是官方注册过的「公式」，只是把官方建议翻成更好记的人话：

  1. 目标：这件事做完，你要解决什么问题？
  2. 来源：它应该看哪里？哪些地方不要看？
  3. 限制：什么不能做？例如不要发送、不要删除、不要下单、不要用过时数据编造。
  4. 交出：你要拿回来的是一份短清单、一封草稿、两个备选方案，还是一张待你勾选的表？最好说明篇幅和格式。
  5. 何时问你：发送、回复、改日历、付款、发布之前，必须停下来等你批准。

这样说，往往不够

「帮我看看最近的邮件，该回的回一下。」问题是：看多久的邮件、什么叫该回、回了是不是直接发出去，都没有说清。

这样说，就接近官方示例

「把未读邮件分成紧急、需要回复、仅供了解三类。给紧急的写好回复草稿，什么都先不要发出去。」这是官方 Inbox manager 示例的意思。

整理收件箱，只起草稿官方 Get started / Use cases 示例的中文表述
请把我的未读邮件分成三类：紧急、需要回复、仅供了解。给紧急的写好回复草稿。任何邮件都先不要发出去。
晨间简报，先不要发送官方 Morning briefing 示例的中文表述
请总结从昨天到现在，我的收件箱、日历、Slack 和文档里有什么变化，并标出需要我亲自处理的事。按一篇可以发到团队频道的草稿来写，但先不要发出去。

这两段都需要先接上相应的应用，才会做得比较稳。若你还没接邮箱或日历，先用第一课那种不依赖登录邮箱的任务来练交代，第四课再接工具。

结果不对时，怎么改，而不是重写人生

官方在讲例行任务之前有一句很实在的话：先告诉助手要改什么、哪些偏好要保留，比如报告的格式。任务做对了，再让它按日程去做。见 Get started 第 5 步。所以第二课的习惯是：

  • 先指出哪一条不对，不要整段作废后从头再来。
  • 把你希望长期记住的规矩告诉它，并明确说「请记住」；把只跟这一次有关的细节写在当天的那条消息里。这是官方在 How Grok Bot works 里的建议。
  • 会变动的数字，例如价格或预算，请它再查一遍，不要只靠记忆。

批准卡片出现时怎么办

官方说明：助手在运行命令、使用应用或在电脑上行动之前，会先经过 Auto Review（自动审查）。默认是打开的。多数动作会自行通过；需要你出面时，就会出现批准卡片，写明要做什么，然后等待。你可以在 Settings → General（设置 → 常规）里，用白话给自己加规则，例如「发送邮件」选 Ask first（先问我）或 Allow automatically（自动允许）。「先问我」的规则会拦住匹配的动作。官方建议：对发送、发布、删除这类不容易撤回的事，加上明确的「先问我」规则。见 How Grok Bot works。

安全提醒

不要把密码、一次性验证码或密钥贴进普通对话。官方要求：密码走 Vault（保险库）、已连接的密码管理器或 Secure Form（安全表单）；银行卡走保险库或安全表单；API 密钥走安全密钥卡片。见 Vault and secure sign-in。

一个可照着做的小练习

把你昨天随口说过的一句含糊任务，按「目标、来源、限制、交出、何时问你」重写一遍，发给助手。然后对照结果：它有没有漏掉限制，有没有多做了你没让做的事。把你改过的那句保存下来，第三课会用到。

会议前一页纸官方 Meeting prep 示例的中文表述
请帮我准备下午 2 点的会：参加的人有谁、我们上次聊到哪里、还有哪些没了结的事项。请控制在一页纸以内。不要发消息给任何人。

常见错误

  • 只说「聪明一点」「按专业的来」，却不说交出品长什么样。
  • 忘记写「不要发送 / 不要发布 / 不要下单」，等于把最关键的刹车留给运气。
  • 把一次性细节和长期规矩混在一句很长的话里，下次又得重新解释。
  • 看到批准卡片就习惯性全点同意。先读卡片上要做的事，再决定。
  • 在对话里粘贴密码或验证码。这是官方明确不建议的。

第三课

一个助手先做好一件事；什么时候再考虑加助手

第一个助手跑通以后，很多人会立刻想「再加几个，组成团队」。官方的建议正好相反：大多数助手最适合只做一件清楚的事；先把这一件事做稳，再考虑分身。

这课学什么

分清两种助手：一个是你的主助手（官方叫 primary Bot，默认名字常是 Grok Bot），负责当你的联络入口，也可以把活转给别人；其余的助手，最好一人一事，把这件事的规矩和记忆慢慢攒下来。你还会学到：什么时候该新建助手，什么时候还早。

为什么重要

官方写得很直白：一个只做一件事的助手，会积累更有用的上下文，比一个什么都管的帮手更靠谱。见 Get started 和 How Grok Bot works。你如果一上来就让同一个助手既管收件箱，又管写稿，又管订机票，它更容易把不同事的规矩搅在一起。

怎么做

先用好主助手

官方建议：新的工作先交给主助手。当同一类请求反复出现，而且有自己的资料来源、规矩或日程时，再给它单独建一个助手，或请主助手帮你建一个。专职助手会为那份工作建立记忆，你不必每次重新解释。

关于记忆，官方还说了两件重要的事：每个助手有自己的记忆，会记住你的偏好、你要求它遵守的规矩，以及带日期的工作记录；但有些关于你的基本情况，例如姓名和时区，是所有助手共享的。所以「时区」说一次就够了；「报销单交到哪个文件夹」只告诉负责报销的助手即可。

需要第二个助手时，这样建

  1. 在侧栏顶部选择 New Bot（新建助手，加号按钮），或按快捷键 Cmd/Ctrl+N。给它起一个能看出职责的名字，再选择 Create（创建）。若你在团队里，加号会打开菜单：可创建新助手，或浏览同事分享的 Team Bots（团队助手）。
  2. 在给它的第一条消息里，只交一份工作，并请它记住你希望这件事怎么做。之后若要改名：点击对话顶部的名字打开详情，再点一次名字即可编辑。
  3. 把第二课里已经说清楚的目标、限制和交出品，写进这第一条消息。不要同时塞三份互不相关的工作。
给专职助手的第一条消息示例常见写法，依据官方「一人一事、请它记住」整理
你专门负责我每周的竞品速览，不做别的事。请每周查看我指定的三家对手，只收集它们公开发布的产品、价格或声明，列出带链接的短清单，并说明对我对外表述可能有什么影响。请记住：不要联系任何人，不要发布内容，不确定的信息标成「未核实」。现在请先按这个标准做一次本周速览，做完先给我看。

什么时候再加助手，什么时候先不要

可以考虑加一个

  • 同一件事你已经手动做对不止一次。
  • 它有自己固定的来源、规矩或日程，例如「每周一看这三家」。
  • 它需要单独的批准边界，例如「只起草稿，绝不发送」。

现在先不要加

  • 第一件事还没做对，或你还说不清交出品。
  • 只是觉得「多几个比较高级」。
  • 还想让一个助手把所有生活和工作都包下来。

官方说法 · 共用一台电脑

你名下的所有助手，共用同一台云端电脑：浏览器登录状态、文件、命令行凭据都是共享的。一个助手登录过的网站，其他助手也能进。官方提醒：不要把别的助手不该使用的凭据或文件放在这台电脑上。助手之间并不是互相隔离的安全房间，只是各自有一块屏幕，可以同时干活。见 Use the computer and apps。

常见做法 · 先别急着组团队

官方在用例里确实写了「几个助手一起完成更大目标」，也提到一个叫 dr eggbot 的助手，会先问你几个问题，再按一人一事帮你把助手搭起来。这是后一步。对本课的学员，先把一个专职助手做稳，比同时管理三个还没有规矩的助手更重要。中文讨论里也常有人把内容生产拆成「一人一段」，原则可以听，但不要把「多助手就能月入多少」这类说法带进今天的练习。

一个可照着做的小练习

看你第一课、第二课反复在做的那件事。如果它已经有清楚的来源和限制，就新建一个只做这件事的助手，把第一条消息写完整，让它先做一次给你看。如果还没有反复做对，就先不要新建，继续在主助手里打磨那一件事。

常见错误

  • 给助手起名叫「全能助手」「万能秘书」，然后把互不相关的事都丢给它。
  • 还没做对一次，就同时建五个助手，结果每个都要重新解释。
  • 忘了所有助手共用登录状态：你让一个助手登上某家购物网站后，其他助手理论上也能用这个已登录的会话。官方在 Grok Bot 101 里把这一点写得很明确。
  • 把团队协作、互相派活当成入门第一课。那是后一段路。

第四课

接上日常工具：邮箱、日历，以及中国用户常问的微信

助手真正省时间的时刻，通常不是它会搜索，而是它能读你已经在用的邮箱、日历和文档，把「要你亲自处理的事」拎出来。这课先学官方支持的接法，再单独说微信和隐私。

这课学什么

学会用 Connect apps（连接应用）把常用工具接上；知道「已添加」和「已登录」不是一回事；理解连接是对整个账号生效的。若你想让助手整理微信聊天，会听到明确的隐私提醒：那不是官方文档里的现成应用，不能把别人的对话随手交出去。

为什么重要

官方用例写得很具体：接上邮件、日历、聊天和文档后，你的每个助手都可以在这些地方阅读和办事；某项服务如果没有对应应用，助手就改用云端电脑上的浏览器。有应用时，走应用通常比在网页上一点一点点更稳妥。见 Use the computer and apps 和 Use cases。

官方举过这些适合入门的例子：Gmail 可以在你起床前把夜间邮件分类，并写好回复草稿等你发送；Google Calendar 可以在周日晚上查看下周安排，标出冲突和排得太满的日子，给你一份周一用的短计划。这些都要先把应用接上，而且发送、改日程这类动作仍然建议先经你同意。

怎么做

  1. 打开侧栏里的 Connect apps（连接应用）。手机上先点左上角头像，再选 Connect apps。也可以在对话里出现 Connect（连接）卡片时，按卡片走。
  2. 浏览或搜索你要的应用，然后添加。常见、且官方文档明确写到的有 Gmail、Google Calendar、Google Drive、Slack、Outlook、Notion 等。本课不把清单说成「全部」，因为目录会更新，以你软件里当时能搜到的为准。
  3. 当 Grok Bot 请你 Authorize 或 Authenticate（授权 / 认证）时，在浏览器里完成该服务的登录。若没完成，可在应用上选 Reconnect（重新连接），或在卡片上选 Reopen（重新打开）。官方提醒：请在大约 10 分钟内完成登录，否则从卡片重新开始。
  4. 确认该应用出现在 Installed（已安装）下面。注意：Added（已添加）只表示安装了，不表示已经登录。若助手说找不到应用，打开它，若显示 Needs auth 或 Disconnected（需要认证 / 已断开），再选 Authenticate（手机上是 Authorize）。
  5. 在对话里用 @ 把这个应用附到任务上，然后用第二课的方式交代。你也可以直接对助手说「请添加 Linear 应用」这类话，让它帮你在目录里找并安装，需要登录时仍会弹出连接卡片。

官方说法 · 连接后的权限和范围

应用连接属于你用来登录 Grok Bot 的同一个账号，并且对你名下所有助手生效。应用能做的事，不会超出你在那个服务里本来就能做的范围。Gmail 可以搜索和阅读、起草和发送、打标签；Google Calendar 可以查看你能看到的日历、创建和更新事件、查看空闲时间、在你能编辑的日历上回应邀请。Slack 是以你连接的那个用户身份发帖，不是另有一个需要被邀请进频道的机器人。应用的登录凭据留在连接服务端，不会交给助手本身。详见 Use the computer and apps。

登录网站时，官方推荐的顺序

有些事情没有现成应用，助手会在云端电脑的浏览器里打开网站。官方写明，它找登录信息的顺序是：先看你存在 Vault（保险库）里的登录项，再看已连接的密码管理器（例如 1Password），再不行就用 Secure Form（安全表单）请你填写。表单里的内容会直接填进页面，助手看不到密码。若遇到统一登录、通行密钥、它过不去的验证码、需要在另一台设备上确认，或必须由人完成的步骤，助手会把电脑交给你：在请求上选择 Open computer（打开电脑），再选 Take control（接管），只完成被卡住的那一步，然后告诉它继续。见 Vault 与 Get started。

浏览器里的登录状态通常会保留，不必每次任务都重新登。也正因为浏览器是共享的，你给一个助手登录过，其他助手也能用这个会话。

中国用户若想到微信

先说清楚界限：截至本讲义整理时，官方公开文档在讲连接应用时，举例是 Gmail、Slack、日历、文档这类服务，并没有把微信写成官方自带的一键应用。因此，下面不是「按官网这五步就能接通微信」的操作手册，请不要把任何民间步骤当成官方保证。

近两个月中文讨论里，确实有人分享把微信聊天记录交给 Grok Bot 帮忙整理的做法，典型场景是群消息看不完。例如 @KinGao476942 在 2026年10月5日转发的讨论。这属于社区里的常见话题，不是本课要带着你一步步打开微信权限的示范。

隐私提醒 · 请先读完再决定要不要做

  • 微信记录里常常有家人、同事、客户的原话、电话、地址、交易和未公开的工作内容。那些不只是「你的」材料。
  • 不要把整个聊天备份一次性交给助手。若你只是想试能力，先用一段你有权使用、且去掉姓名和敏感细节的样例。
  • 不要在普通对话里粘贴验证码、支付密码或登录凭据。
  • 不要让助手冒充你在微信里群发或私聊；任何对外发送都应先经你过目。
  • 官方也提醒过：所有助手共用那台云端电脑上的文件和登录状态。你放上去的聊天导出，其他助手理论上也能看到。用完后，应删掉不必保留的敏感文件。

常见做法

对大多数学员，第四课更稳妥的路径是：先接官方文档写过的邮箱和日历，把「分类、起草、先不发送」跑通。微信相关的民间接法，请先自己判断隐私风险，再决定要不要另找可靠说明；本课不复述未经官方文档确认的操作步骤。

一个可照着做的小练习

先只接一个你每天都用的工具，例如 Gmail 或 Google Calendar（若你主要用 Outlook，就接官方目录里对应的邮件或日历应用）。接好后，用下面其中一段做一次，并确认它没有擅自发送或改日程：

邮件分类练习依据官方 Inbox manager 示例
请把我的未读邮件分成三类：紧急、需要回复、仅供了解。给紧急的写好回复草稿。任何邮件都先不要发出去。
一周日历预览依据官方 Use cases 中 Calendar 说明改写
请查看我接下来七天的日历，标出时间冲突和排得过满的日子，并给我一份明天可以照着看的短计划。先不要新建、移动或删除任何日程。

常见错误

  • 以为点了添加就等于已经登录。看到 Needs auth 或 Disconnected，还需要完成授权。
  • 一次接很多应用，却还没有把「只起草、不发送」的规矩说清楚。
  • 把官方的「连接应用」和 X / grok.com 上另一个产品里的连接器混为一谈。本课只讲 Grok Bot 应用里的 Connect apps。
  • 为了图快，把微信或其它即时通讯的完整记录导入云端电脑，又没有删除计划。
  • 让助手在你没看过草稿之前，就回复客户或改别人的会议邀请。

第五课

让它按时自动做，不要每次从头说

同一件事你已经手动做对了，就不要天天把说明再打一遍。官方把这件事拆成两块：先把成功的方法存成 skill（技能），再用 routine（例行任务）告诉助手何时开工。

这课学什么

你会按官方顺序做：先完成一次可靠的人工任务，把步骤、判断规则、交出品和安全边界存成技能，再设例行任务——按日程跑，或在某件事发生时跑。你会核对自己的时区、学会先测试再启用，并给发送、购买、删除留审批。主要依据是 Skills and routines。

为什么重要

助手的长处之一，是云端电脑在你合上笔记本之后还能继续工作。可一旦例行任务设错，它也会按错误的方法准时反复做，既费额度，也可能在你不在时越界。所以官方把顺序写死了：先做对，再保存方法，最后才自动化。

怎么做

先把做对的方法存成技能

官方说，一个有用的技能应写清：什么时候用、需要哪些输入和权限、工作顺序、如何验收、交回什么、哪些步骤必须审批。技能可以供你的多个助手使用，但某个助手仍可能需要相应的应用或登录才能真正用起来。若要使用某个技能，在对话里按名字叫它；用 @ 可以提到助手、群组、例行任务和应用。

保存技能的说法依据官方示例改写成更日常的任务
请把我们刚才用的方法存成一个技能，名字叫「每周竞品速览」。请写进来源网站、怎样判断一条信息值得列入、输出格式，以及一条硬规矩：任何对外联系都必须先经过我批准。

官方还提到 Teach a task（教一项任务）：在一对一对话里打开电脑画面，选择该功能，先说明你要演示的结果，自己做一遍，停止录制后检查它生成的技能，再在安全的例子上测试，然后才安排日程。这段演示最多大约 10 分钟，不录麦克风声音。演示时不要暴露密钥，登录仍应走安全交接。若你的软件里暂时看不到这个按钮，官方说可以改口：请助手根据书面说明和刚才已完成的任务来创建技能。该功能可能是逐步开放的。

再请它按点去做

向「应该负责这件事的那个助手」说明：何时运行、用哪份材料、交回什么、哪些动作要审批、来源缺失时怎么办。官方强调：来源不可用时，应报告失败，而不是拿旧数据凑数。

设立例行任务依据官方 Create a routine 的写法改写
请每个工作日早上 8:00（北京时间）运行「每周竞品速览」技能，针对我指定的三家对手，把带链接的短清单发在这个对话里。不要联系对方，也不要发布内容。如果当时打不开来源网站，请直接告诉我失败原因，不要用旧数据代替。
  1. 核对时区。日程使用 Settings 里 Bot 一项下的 Timezone（时区）。Auto-detect（自动检测）跟随这台电脑。若例行任务应当跟办公室所在地走，就手动选一个时区。对大多数国内学员，请确认是北京时间（Asia/Shanghai）。用白话约定时间，例如「每个工作日早上 8 点」，然后打开这条例行任务，查看 When to run（何时运行）里保存的文字是否真是你的意思；不对就选 Edit（编辑），告诉助手要改什么。
  2. 明白它不会在创建的那一刻立刻跑。官方写：新例行任务会等到下一个预定时间。如果你在 8:05 设了「每天 8:00」，第一次要到明天 8:00。想马上试，用 Test（测试）。
  3. 先测试，再依赖它。若该例行任务提供 Test，创建或修改后请打开它并选择测试。按钮会显示 Running…（正在运行），结果出现在该助手的对话里。官方特别提醒：测试会做真实的事，可能打开网站、改文件、调用已连接的工具。请用安全的输入，并把会改动外部世界的动作留在审批后面。
  4. 在详情里管理。电脑上点击对话顶部的助手名，在 Details（详情）里查看例行任务：名称、何时运行，或显示 Paused（已暂停）。用开关即可暂停或恢复。打开一条，能看到 Instruction（每次运行做什么）和 When to run。底部一般有暂停 / 恢复、测试（如有）、编辑和删除。手机上打开助手资料里的 Routines（例行任务），关掉 Active（启用）即暂停。删除不可撤销，删除助手也会带走它名下的例行任务。

官方说法 · 一些数字和限制

一个助手最多可拥有 50 条例行任务；每条只保留最近 20 次运行记录。两条日程之间至少间隔 5 分钟。你的全部例行任务合计每小时最多运行 300 次，单条最多 200 次；超过会失败，并提示额度用尽。官方还提醒：跑得勤的例行任务会消耗更多用量，例如每小时一次、间隔很短，或在很热闹的 Slack 频道里监听每一条新消息，可能一天就用掉本来够用一周的量。先暂停不需要的，再把日程拉疏、把触发条件收窄，而不是先升级方案。详见 Skills and routines。

设计时更放心的原则

官方建议：先自动化「准备」，再考虑「执行」。让助手先起草、核对、给建议；把发送、购买、删除、发布或改生产环境，放到必须批准后面。写明没有数据、或数据过期时该怎么办；若只完成一部分，要它明确汇报。网站或来源改版后，重新测试一遍。

例行任务也可以在「有事情发生时」启动，例如一条 Slack 消息、一封发到助手自己邮箱的邮件，或其它官方支持的事件。入门阶段建议先用「每个工作日几点」这种好检查的日程，并把匹配条件收得很窄。官方明确不建议监听「每一条新消息」，那既吵，又费用量，也更容易对不相干的内容采取行动。

一个可照着做的小练习

选一件你已经手动做对的事（例如每周竞品速览，或工作日早晨的邮件分类）。先请助手把方法存成技能，再设一条「每个工作日某个整点」的例行任务，时区选北京时间，并写明「先不要发送」。创建后立刻做一次 Test，检查：它用的是不是最新材料、格式对不对、有没有在该停的地方停下来。若测试结果不对，先改，再等到下一个预定时间。

常见错误

  • 任务还不稳定，就先设成每天自动跑。
  • 设完以为它会马上执行一次，其实要等到下一个预定时间；又忘了用测试。
  • 时区还停在自动检测到的国外时区，于是「早上 8 点」并不是北京时间的早上 8 点。
  • 触发条件太宽，用量很快用完，还可能在你没盯着的时候对不相干的消息采取行动。
  • 来源网站打不开时，让它「随便用昨天的结果顶上」。官方要求此时报告失败。

第六课

用到工作与内容里：先学会官方那四个角色

到这里，你已经会交任务、会接工具、也会设例行任务。第六课不把销售、法务、招聘那些按岗位写的长指南全部讲完，只把 Grok Bot for Work 里最适合小白的部分讲明白：先解决通信、时间和信息这三件事，必要时再设一个总入口。

这课学什么

理解官方作者 Josh Kim 在 2026年9月24日那篇工作指南里写的四个助手：Inbox Manager（收件箱管家）、Calendar EA（日历助理）、Intel Scout（信息侦察）、Bot Boss（总入口）。你会知道每个角色管什么、默认应守住哪条边界，以及入门时为什么通常先做好一个，而不是四个一起开。

为什么重要

很多人学到后面会散掉，原因是同时管很多「新工作台」。这篇官方指南要解决的，正是日常工作里最耗神的三件事：哪些消息真的要回、时间会不会被别人占满、有哪些重要信息你其实没看到。它不是教你靠助手赚钱，而是教你先把工作中重复出现的准备活，变成可检查的草稿和简报。

怎么做

1. 收件箱管家

官方的用法是：把它接到你的通信工具上，当第一道过滤。作者把自己的设成默认只读：找出既重要又紧急的少数几件事，帮你决定时间花在哪，而不是自动替你回复所有人。入门时请保持同样的刹车：先分类和起草，发送必须等你一句话。

2. 日历助理

它学习并守住你安排时间的方式，例如把会议尽量靠在一起，留下完整的专注时段，或避免晚接到要接孩子的点。官方示例强调：每次先重新拉取日历，不靠过期缓存；先提出冲突和可选方案，经你确认后再起草变动或邀请，绝不悄悄改日历。

3. 信息侦察

作者让它在工作日早 8 点和下午 5 点各跑一次，查看收件箱、Slack 和会议记录，既包括你看到的，也包括你可能错过的。每次只给你三部分：和你或团队相关的动态、还没跟完的事项、下一场会议前需要的信息。没有新情况就保持安静，不编造，不擅自发送。

4. 总入口

三个助手都开始找你说话时，注意力会被重新切碎。所以作者加了第四个：Bot Boss。其他助手的汇报先汇总到它，你只和这一个入口说话；需要发送或改日历时，仍然先起草再等你批准。官方把它写成「总入口和分发者」，不是再去做建设，也不是事后审计的另外一套角色。

官方说法

Grok Bot for Work 页为这四个角色提供了可复制的英文长提示词，里面还有作者自己的时间表和许多细则。那些提示词是作者的完整配置，不是入门必贴的「标准答案」。本课先用下面这些更短、与官方入门示例一致的说法，让你先跑通一个角色。若你稍后想对照原文细调，请打开 Grok Bot for Work。

入门建议：先选一个最痛的点。邮件最多，就先做收件箱管家；会议最多，就先做日历助理。先手动跑对，再设工作日的例行任务，并在启用前保持 Disabled / 先不启用，直到你检查过测试结果——官方作者在长提示词里也写了类似的「先创建为未启用，等我打开」。

收件箱管家，入门版与官方入门示例一致，供先跑通
你专门做我的收件箱管家。请查看未读邮件，分成紧急、需要回复、仅供了解三类，并指出最需要我今天处理的少数几封。给紧急的写好回复草稿。默认只读：不要发送、不要回复、不要擅自加星或归档。不确定的地方请标明「未核实」，不要编造紧急程度。现在先做一次给我看。
日历助理，入门版依据官方 Calendar EA 职责改写的短版
你专门做我的日历助理。请先重新拉取我的日历，标出冲突、专注时间被打断，以及可能赶不上固定私事的安排，并给出可选择的调整方案。先不要改日历、不要发出邀请。等我确认后，再起草变动，仍先给我看一眼。现在请先看接下来七天，做一次检查。
若要写内容，也先起草官方 Content marketer 用例的中文表述
请从本周已经发布的更新和相关讨论里，起草一封简报和三条帖子，语气跟我们平时对外说话的方式一致。只把草稿给我，不要发布任何内容。

写内容时，仍然建议一人一事：一个助手负责收集已发布的事实，一个负责按你的语气起草，发布前由你过目。原则来自官方「一人一事」和「发布前审批」。不要把「一周做多少条、能赚多少钱」当成这课的目标。

一个可照着做的小练习

只选一个角色，用上面的短提示跑通一次，检查三件事：它有没有编造、有没有在该停的地方停住、交出品你能不能直接拿来用。满意后再设工作日的例行任务，先测试，再启用。四个角色都想要时，也请一个一个加；总入口是最后一步，不是第一步。

常见错误

  • 把官方长提示词整段贴进去，却还没接上邮箱或日历，结果什么都做不了。
  • 四个助手一起启用，每个都在工作日早晚找你，注意力比以前更碎。
  • 让收件箱管家直接代发，或让日历助理悄悄改会议。
  • 把这份工作指南理解成「用助手赚钱秘籍」。原文讲的是沟通、时间和信息。
  • 还想把销售、法务、招聘的全部官方指南在一节课里讲完。那些适合按自己的岗位课后选读，入口在 x.ai/bot/guides。

课后提醒

常见坑，以及这门课不要去追的东西

学 Grok Bot 时，最容易耽误你的，往往不是功能太少，而是路上的噪音太多。有些内容流量很大，却不适合当成这门课的主线。

先避开这些常见坑

  • 收藏了十几篇教程，一件小事都还没交出去。这正是 @Mulight 提醒过的毛病。先交一件每天重复的小事。
  • 把 X 里的 Grok 技巧，直接当成 Grok Bot 的功能。例如在帖子右上角点 Grok 图标、做检索判断。那些可以另说，但不是这门课里的桌面助手。
  • 还没做对，就先上自动。官方顺序是：一次任务做可靠，存成技能，再设例行任务。
  • 不设刹车。发送、发布、付款、删除之前，应留下「先问我」。官方还写过：若你希望每次付款都亲自批准，就不要把卡存进 Vault，因为已保存的卡在结账时可能直接填入。
  • 忽略「一台电脑大家共用」。一个助手登录过的网站，其它助手也能进；放在云端电脑上的文件，其它助手也能看到。
  • 在对话里粘贴密码、验证码或密钥。请走保险库、安全表单或安全密钥卡片。

这些不要当主课去追

下面几类在公开讨论里经常出现，有的浏览量也很高。本课的态度是：知道它们存在即可，不要当成从零学会用的主线。

  • 赚钱秘籍、自动接单、包装成「月入多少」的内容流水线。助手可以帮你起草内容，但不能把营销承诺当成操作教程。
  • 币圈、打新、自动炒股技巧。其中有些写的其实是通用 Grok，不是 Grok Bot；而且涉及交易风险，不适合当入门课。
  • GitHub 自托管清单、复刻旧版、补接一堆工程工具。这类清单常被重复转发，对零基础学员过深，也不是「今天就能用起来」的路径。
  • 给工程师的评测、持续集成、云端编码工作坊。那是另一门课。本课停在：会交代、会接日常工具、会设例行任务。
  • 只列出「能做调研、能写文案、能剪视频」、却没有步骤的能力清单。听起来什么都会，学完还是不会下手。

课后若还想学

官方指南总入口是 x.ai/bot/guides。先把 Get Started、Grok Bot 101、Grok Bot for Work 吃透。销售、市场、客服、招聘那些按岗位写的指南，按你自己的工作选一篇照着做即可，不必一次读完。社区里也有人整理学习目录或指南站，例如 @xiaomovps、@WhitneyEnlow、@cgnot996、@iiiichigo_chan 的路径帖，以及 @SIAxiom 推荐的 hireagrokbot.com/guides。那些适合当课后索引，不要在还没跑通第一件事之前一篇篇看完。

课后练习

今天就能动手的五件小事

不必一次做完。按顺序往下做，已经会的可以跳过。每件事都请把「先不要发送、不要发布、不要下单」写进去，并亲自看结果。

  1. 装好并交一件不依赖邮箱的小事。例如按第一课的提示，查一个真实行程或三家对手的公开动态，只要两份备选或一份带链接的短清单。检查它有没有编造、有没有按你的禁令停住。
  2. 把一句含糊的话改写成完整交代。用第二课的五问重写，再发一次。把你满意的那一版留下来。
  3. 只在「已经做对」的前提下，考虑第二个助手。若这件事有固定来源和规矩，就新建一个只做这件事的助手，把第一条消息写完整。若还没做对，就先不建。
  4. 接上一个日常工具，做一次只读练习。优先接官方文档写过的邮箱或日历。让它分类或检查冲突，但不要发出邮件、不要改日程。若你想到微信，先重读第四课的隐私提醒，本练习不要求你接通微信。
  5. 把做对的方法变成一条例行任务。先存技能，再设「每个工作日某个整点、北京时间」运行，先测试，再启用。确认 When to run 里的文字和你想的一致。

若某一步做不下去

官方建议：先完全退出应用再打开；仍不行再看 Get started 里的故障排除，或联系官方支持。登录完不成、看不懂某个按钮时，把屏幕上的英文原文记下来对照文档，不要根据印象猜测下一步。
